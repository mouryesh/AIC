# Decision-vs-outcome stress test

> **This is a simulated prototype result on synthetic data**, generated by
> `python -m rippletwin.evaluation.stress_test` from `results_stress_test/tables/`
> — a separate results directory from `results/tables/` (see
> [docs/RESULTS.md](RESULTS.md)), never written into in place.

Following Saad Saoud (2026), "Ground-Truth-Aware Stress Testing of a
Closed-Loop Digital Twin Under Sensor Drift and Missing Data"
(arXiv:2608.14917), this asks a question the flagship coverage sweep does
not: not "how accurate is the twin," but **"how often does sensor
corruption actually change the decision the twin would make"**, holding
the physics fixed and varying only what a plant can see. The same
paired/common-random-numbers design `evaluation.experiments.run_experiment`
already uses for its coverage sweep — one physics run per episode, viewed
at multiple observability levels — is reused here, extended with dynamic
sensor faults (`factory.sensor_health`) layered on top of a coverage view.

Decision proxy: `(top_station, detected)` — did the twin's leading suspect
or detection state change, compared against a paired oracle run at full
observability with no sensor faults. This is a simpler proxy than
`recommend.dispatch`'s full action payload; see the module docstring in
`src/rippletwin/evaluation/stress_test.py` for the scoping rationale.

## Mandatory self-check

Every stress condition is compared against an **oracle pass on the exact
same episode** (same seed, same physics). Comparing the oracle against
itself must always show zero decision mismatch — if it doesn't, the
harness itself has a bug and no other number in the run can be trusted.

**Result: `results_stress_test/tables/oracle_self_check.csv` — every
`self_mismatch_rate` across all 24 held-out test episodes is exactly 0.**
The self-check passed.

## Decision mismatch rate vs. outcome gap

24 held-out test episodes (seeds 5000–5023), same `ExperimentConfig` as the
flagship run.

| Condition | Coverage | Fault | n | Mean decision-mismatch rate | Median outcome gap (stations) |
|---|---|---|---|---|---|
| `cov75_clean` | 75% | — | 24 | 0.350 | 0.5 |
| `cov75_dropout30pct` | 75% | DROPOUT, 30% of run | 24 | 0.350 | 0.5 |
| `cov75_stale30pct` | 75% | STALE, 30% of run | 24 | 0.379 | 0.5 |
| `cov50_clean` | 50% | — | 24 | 0.592 | 1.0 |
| `cov50_noisy30pct` | 50% | NOISY, 30% of run | 24 | 0.592 | 1.0 |

("Outcome gap" is the median absolute station-index distance between the
oracle's and the stress condition's named station, on windows where the
oracle detected something — a cheap proxy for "did the consequence change,"
not the paper's own methodology, which this repository has no equivalent
measurement for; see the module docstring.)

## Honest reading

- **Coverage loss dominates fault severity.** Dropping from 75% to 50%
  coverage roughly **doubles** the decision-mismatch rate against the
  oracle (0.35 → 0.59), independent of whether a dynamic sensor fault is
  layered on top. This matches the flagship coverage sweep's own finding
  that observability, not any one failure mode, is the first-order driver
  of localisation difficulty.
- **The dynamic faults tested here (one faulted station, 30% of the
  episode's duration) move the mismatch rate only slightly on this line
  at this severity** — DROPOUT at 75% coverage is statistically
  indistinguishable from clean (0.350 vs 0.350), STALE moves it by about
  three points (0.350 → 0.379), and NOISY at 50% coverage shows **no
  measurable change at all** (0.592 vs 0.592). This is a real, reported
  result, not a null result being explained away: a single mid-line
  station corrupted for less than a third of the run is a comparatively
  mild insult against a twin whose flow-conservation reasoning already
  degrades gracefully (see `docs/METHOD.md` §3.1 on graceful degradation
  under partial evidence). A harsher grid — more faulted stations,
  faults nearer the true constraint, longer fault duration — would be
  needed to separate "sensor faults barely matter here" from "this
  particular grid was too mild to move the needle"; this run does not
  distinguish the two, and should not be read as evidence that dynamic
  sensor faults are unimportant in general.
- **Every stress condition's oracle self-check was exactly zero** across
  all 24 test episodes, confirming the harness's paired comparison is
  wired correctly before any of the above numbers are trusted.
