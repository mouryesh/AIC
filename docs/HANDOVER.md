repository publishes this work, so it is your call, not an automated step. There
is also no GitHub CLI installed in this environment and no credentials were
read or used.

README, no .gitignore — the repo already has both), then:

```bash

git remote add origin https://github.com/<YOUR-USERNAME>/RippleTwin.git

```

```bash

```

data. `data/` is intentionally empty — every dataset is a deterministic function

## If a judge asks one question, it will be one of these

Prepared answers for 33 of them: [`JUDGE_QA.md`](JUDGE_QA.md). The three most
likely:

**"Isn't this just anomaly detection?"** No — anomaly detection cannot tell a
cause from a victim, and under a bottleneck the victims look far more anomalous
than the cause. Baseline B1 is exactly that, given the same features, and it
locates the source in 0% of hidden-source cases.

**"How do you know the hidden state is right?"** We estimate the cycle time of a
station that has no sensor to ~3% median error, graded against ground truth the
model never sees.

**"Your simulator is built to make your method work."** It broke two of our own
designs, both documented in `METHOD.md`. A simulator built to flatter the method
would not have done that.

## What we would fix first with more time

1. **Validate the flow signature on one real line's PLC logs.** This is the only
   thing that moves the work from plausible to proven, and nothing else comes
   close in value.
2. **Generalise beyond serial topology** — parallel sub-lines and rework loops
   need the propagation matrix rebuilt from the real process graph.
3. **Strengthen the quality path.** Median rank 7 of 42 is a useful shortlist,
   not a diagnosis.
4. **Detection at low coverage.** At 25% instrumentation, exact localisation
   falls to ~16%. Honest, but that is the edge of the mechanism.
